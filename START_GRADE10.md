## 2. КАК УСТРОЕН УРОК

**15 экранов:** 1 хук · 2–8 объяснение (8 — правило) · 9–14 практика · 15 итог.

**Каждый экран объяснения — «показ, потом работа»:**
сначала один-три кадра с озвучкой, где чертёж живой, а справа строка за строкой ложится
решение (ученик не нажимает ничего); потом тот же чертёж становится рабочим.

**Показ не решает задачу ученика.** Три приёма, все применены в уроке 3:

| Приём | Где |
|---|---|
| вывод на общем случае, проверка руками на частных | слайд 3: `cos²α + sin²α = 1` из Пифагора |
| опровержение догадки без выдачи ответа | слайд 4: `(1/2)² + (1/2)² = 1/2`, а нужна единица |
| способ на числе, которое проходит; задание — на том, что не проходит | слайд 7: показ на 0,6, задание 1,2 |

**Разобранный образец убирается из задания.** На слайде 6 разобрана точка 180°, ученик проходит
только 0°, 90° и 270°.

**Файл урока — только данные.** Механика в `tools.jsx`, инфраструктура в `core.jsx`,
обвязка экрана — в `screens.jsx`. Копировать инфраструктуру между уроками нельзя.

**Как делается новый урок**

```
node scripts/grade10-new-lesson.mjs 4 dars04-ishoralar "Ishoralar" "Signs"
```

Команда берёт тему **из плана дословно**, ставит границы блока, пишет пятнадцать экранов с
объявленными ролями и добавляет запись в реестр. Дальше заполняются данные по скелету, и урок
проверяется четырьмя скриптами из §4.

В файле урока каждый экран объявляет `role` (роль по эталону §4.1), `answer` (как сдаётся
ответ) и в блоке практики `format`. По этим полям машина сверяет план урока с контрактом.
Цвет в данных не хранится: метка на окружности задаётся смыслом (`tone: 'graph'`).

## 3. РЕШЕНИЯ МЕТОДИСТА, КОТОРЫЕ ДЕЙСТВУЮТ

1. **Прибор — контролёр, не оракул.** Ответ не показывается до действия. Чертёж-подсказка
   появляется только после ошибки.
2. **Панель показаний — табло:** название над значением, значение 19–29 px. Живёт в колонке
   записи, внутри прибора не рисуется вовсе.
3. **Прибор без показаний = выключенный прибор:** шкала видна, на месте значения серая чёрточка.
4. **Обе координаты выводятся,** а не только синус. Связка заканчивается парой `(cos α; sin α)`.
5. **Вывод показывается целиком, включая подстановку** (`sin α = a / 1`). Зелёным — ровно одна
   строка на кадр, вывод текущего кадра.
6. **Если озвучка говорит «движется» — на экране движется, пока она это говорит.**
7. **Объекты не подменяют друг друга, а превращаются:** колесо → треугольник → единичная
   окружность это одна фигура, общие линии не пропадают.
8. **У задания свой знак:** акцентная полоса, рисованный знак жеста, глагол (ВЕДИ, ВЫБЕРИ,
   НАБЕРИ, РАССТАВЬ, СОЕДИНИ, ОТМЕТЬ ВСЕ, ЗАПОЛНИ). Виден только пока действие не сделано.
9. **Разбор молчит до первого действия** — он ответ на действие, а не копия инструкции.
10. **Ссылок на страницы учебника на экране и в озвучке нет** — источник живёт в документах.
11. **Пустых мигающих рамок нет.**
12. **Оценивается только блиц** (экран 14). Остальное — теги, не проценты.
13. RU — «ты», прошедшее время без рода. UZ — `siz`, апостроф ASCII. Озвучка мужская (`g=m`).

Полностью и с обоснованиями — `ETALON_10SINF.md` §5–§8.

## 4. КАК ПРОВЕРЯТЬ

Скрипты, которым нужен браузер, принимают урок аргументом — по умолчанию урок 3:

```
node scripts/grade10-noscroll.mjs dars01-radianlar
node scripts/grade10-hand.mjs dars01
node scripts/grade10-tts-check.mjs dars01
```

У `grade10-hand.mjs` на каждый урок свой план нажатий: проверка «проходится ли руками» обязана
знать, что именно делать на каждом экране. План живёт в самом скрипте, рядом с планом урока 3.

```
npx vite --port 5210 --strictPort        # в отдельном окне
node scripts/grade10-noscroll.mjs        # ~7 минут, 1776 измерений
node scripts/grade10-lesson-audit.mjs    # секунда, контракт эталона
node scripts/grade10-lang-check.mjs      # секунда
node scripts/grade10-tts-check.mjs       # минута
npx vite build
```

`grade10-noscroll.mjs` ходит по 15 экранам, нажимает каждый шаг открытия, на 5 размерах
(1366×615, 1366×655, 1920×950, 390×745, 360×690) и 3 языках. Ловит: прокрутку, обрезку внутри
карточек, шрифт мельче 10,5 px, показания прибора мельче 18 px, чертёж мельче пола, кириллицу
в UZ и EN, ошибки консоли.

`grade10-lesson-audit.mjs` — контракт эталона без браузера: пятнадцать ролей в порядке §4.1,
тег на каждом экране 2–14 и только из списка эталона, пороги §4.6 (не больше трёх экранов с
выбором, не меньше трёх с записанным ответом), четыре варианта и свой разбор на каждый неверный,
три непустых языка, апостроф ASCII, отсутствие символов в озвучке, метка урока и запись в реестр.
Список тегов читается **из эталона**, поэтому добавленный в §2 тег скрипт принимает сам.
Ключ `--release` делает жёсткой проверку `FREE_NAV`.

Урок объявляет для этого три поля на каждом экране: `role` (роль по §4.1), `answer` (как
сдаётся ответ) и, в блоке практики, `format`. Без них роль экрана проверить нечем.

`grade10-apostrof-fix.mjs` — чинит типографский апостроф из PDF учебника (`ʻ`, `'`) на ASCII `'`
и переводит такую строку в двойные кавычки. Разбор посимвольный: регексом по кавычкам файл
рвётся, проверено.

`grade10-lang-check.mjs` — статический: непереведённые строки в колонке записи и обратные
кавычки внутри шаблона CSS.

`grade10-tts-check.mjs` — открывает урок с `?tts=<база>`, перехватывает запросы озвучки и
проверяет, что в каждом стоит ведущий маркер языка (`[Русское произношение]` /
`[O'zbekcha tallaffuz]` / `[English pronunciation]`), `lesson_id`, `lesson_name` с номером
урока и `g=m`. Без маркера голос читает базовый язык неправильно — это требование платформы,
такое же, как во 2 и 3 классах.

**Урок, на котором любой скрипт упал, на приёмку не приносится.**

## 5. ГРАБЛИ, НА КОТОРЫЕ УЖЕ НАСТУПАЛИ

- **Обратная кавычка в комментарии внутри `STYLES`** рвёт шаблон, кусок комментария становится
  кодом, урок не открывается: `ReferenceError`. За проект — **четырежды**, последний раз
  2026-08-12. Ловится только сборкой, и то сообщением про «пропущенную точку с запятой» в
  случайном месте. В том месте кода теперь стоит предупреждение.
- **Подпись-слово в приборе надо пропускать через перевод.** `L(...)` — это объект; выведенный
  напрямую, он роняет весь урок («Objects are not valid as a React child»). Так падал экран 10
  урока 1 на всех размерах, при зелёном контракте и успешной сборке.
- **Экран не влезает — сначала измерь, потом правь.** `grade10-hand.mjs` печатает состав экрана
  с высотами блоков. Полдня ушло на попытки «ужать чертёж», который держал `min-height` и не
  сжимался вообще.
- **Проценты высоты внутри flex не считаются:** SVG вырастал с 216 до 904 px. Размер даёт
  `Scene` через `useBoxSize` и `cloneElement`.
- **Панель рядом с чертежом обрезается молча:** сцена считает бокс квадратом.
- **Кнопки сайта фиксированы поверх страницы** (слева «Darslar ro'yxati», справа язык, полоса
  y 16..56) и накрывали кнопки урока на всех ширинах до 1440. Проверять только измерением
  пересечения прямоугольников, глазами не видно.
- **На 360 px вся страница сжимается на 7,7 %** (холст 390 px) — размеры мерить по вёрстке
  (`offsetWidth`), иначе к узкому экрану требования жёстче.
- **Старый процесс Vite держит порт и отдаёт устаревший модуль.** Убивать по PID:
  `Get-NetTCPConnection -LocalPort 5210`.
- **Строка записи со словом обязана быть `L(uz, ru, en)`.** Простой строкой пишется только
  формула, иначе узбекский текст выводится на русском экране.
- **`Math_1-11_Поурочно_RUz.xlsx` в `src/books` битый.** Читаемая копия — в
  `_archive/duplicates/…(2).xlsx`. Актуальный план — `_v4 (2).xlsx`.

## 6. ПЛАН И ЕГО ГРАНИЦЫ

53 урока, сплошная нумерация, ПК и ИК исключены. Строка плана = номер урока + число ПК до него.

**План не совпадает с узбекскими учебниками 2022.** Производной (уроки 14–25) и пространственных
векторов (48–53) в учебниках нет; многогранники есть частично. План утверждён предметником, то
есть побеждает он, но для этих блоков не будет ни образца изложения, ни терминологии из учебника.
Блок Б8 (векторы, ДТМ) ждёт согласования специалиста по ДТМ — в производство не берётся.

Сроки по v4: старт 14.08, дедлайн 23.08.2026, исполнитель Аяна, практика 53×10 тестов.

## 7. ЧТО СКАЗАТЬ В НОВОЙ СЕССИИ

Достаточно одной строки:

**«продолжаем 10 класс по START_GRADE10.md»** — и дальше что нужно, например:

- «продолжаем 10 класс по START_GRADE10.md, урок 4» — новый урок, начнём со скелета;
- «продолжаем 10 класс по START_GRADE10.md, правки по уроку 3: …» — доработка пилота;
- «продолжаем 10 класс по START_GRADE10.md, QA урока 3» — прогон проверок и отчёт.

Порядок работы над новым уроком не меняется: **скелет → контент → сборка → QA**, скелет и
контент идут на утверждение до сборки.
