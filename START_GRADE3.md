# START_GRADE3 — входной документ для работы над 3 классом

> **Как этим пользоваться.** В начале любой новой сессии по 3 классу методист говорит:
> «прочитай `START_GRADE3.md` и работай по нему». Этот файл — единственная точка входа.
> Он не заменяет `ETALON_3SINF.md` (методический контракт), а объясняет, **как** по нему
> работать: где источники истины, с чего начинать, каким должен быть результат и на каких
> граблях здесь уже стояли.
>
> Область действия — **только 3 класс**. Классы 1, 2, 5, 6 по решению методиста
> (2026-08-03) не трогаем.

---

## 1. Что такое эталон 3 класса

**Эталон — это контракт, который урок обязан выполнить. Не файл, который надо скопировать.**

Это различение — главное в документе. В проекте слово «эталон» долго означало две разные
вещи, и их смешение производило и копипасту, и баги:

| | Эталон-контракт (правильно) | Эталон-файл (то, во что превратилось) |
|---|---|---|
| Где | [src/books/grade3/ETALON_3SINF.md](src/books/grade3/ETALON_3SINF.md) | `Dars01.jsx`, `Dars15.jsx` |
| Что переносится | требования к уроку | строки кода |
| Как проверяется | валидатором по критериям | сравнением глазами |
| Исправление бага | в одном месте | в каждом файле заново |

Сам `ETALON_3SINF.md` говорит об этом прямо (стр. 3–7): новый урок
«**tashqi ko'rinishini ko'chirish bilangina cheklanmaydi**» — не сводится к копированию
внешнего вида; сохраняются педагогический поток, двуязычность, управление аудио,
обучение на ошибке и итоговая диагностика.

**Эталонные уроки 3 класса — это `Dars01`–`Dars18` и `Dars21`** (19 файлов). В них аудио
написано вручную, интерактивность разнообразная. Они — образец **уровня**, а не исходник
для копирования.

## 3. С чего начинать работу — процедура

0. Если нужно понять устройство кода, термины или найти причину бага —
   [GRADE3_SPRAVOCHNIK.md](GRADE3_SPRAVOCHNIK.md): карта файла урока, словарь терминов,
   таблица «симптом → где смотреть».
1. Прочитать этот файл целиком.
2. Прочитать `ETALON_3SINF.md` — все 8 разделов.
3. Понять, к какому блоку сюжета относится урок (`SYUJET_3SINF.md`), какое препятствие
   Lumo он снимает и какой мостик ведёт к следующему уроку.
4. Проверить `src/lessons/grade3.js`: номер, slug, тема, описание.
5. Собрать скелет по **15 ролям** (§4.1 ниже) — не по числу экранов.
6. Заполнить контент: RU + UZ + аудио-триптих на каждый экран (§4.2).
7. Прогнать проверку готовности (§7).
8. Показать методисту. Он прокликивает и правит.

**Этапы не пропускаются.** Скелет — не бюрократия: это место, где ловятся ошибки методики
до того, как они закостенеют в контенте.

### 4.1. Пятнадцать роли экрана

Тип экрана = **педагогическая роль** из `ETALON_3SINF.md` §1, а не позиция (`Screen0…Screen15`).
Это то, что делает эталон машинно проверяемым: можно спросить «есть ли в уроке обратная
задача?».

| # | Роль (ключ) | Задача |
|---|---|---|
| 1 | `entry_diagnostic` | проверяет прежнее знание, не спрашивает новое правило |
| 2 | `recall` | активирует одно опорное знание |
| 3 | `problem` | показывает препятствие в сюжете Lumo |
| 4 | `concrete_model` | модель на видимом объекте |
| 5 | `second_model` | то же в другом изображении |
| 6 | `discovery` | ребёнок предсказывает результат или выбирает закономерность |
| 7 | `rule` | открытая связь коротко называется |
| 8 | `guided_practice` | один шаг, сильная визуальная опора |
| 9 | `directed_practice` | опора уменьшается |
| 10 | `independent_practice` | новый пример, без опоры |
| 11 | `reverse_task` | из ответа восстановить действие/число/модель |
| 12 | `error_find` | найти и исправить типичную неверную мысль |
| 13 | `life_problem` | математика решает реальную проблему сюжета |
| 14 | `final_diagnostic` | трансфер, не повторяет числа урока |
| 15 | `summary` | что усвоено, препятствие снято, мостик дальше |

13–16 содержательных экранов. Простые роли могут объединяться в одном экране, сложные —
делиться на несколько. **Меняется число экранов, не набор ролей.**

### 4.2. Контракт данных урока

Формальная версия — в [src/courses/grade3/kit/schema.js](src/courses/grade3/kit/schema.js).
Суть:

```js
{
  role: 'discovery',            // одна из 15; позиционных Screen0..N больше нет
  interaction: 'numpad',        // mc | numpad | drag | order | match | numline | tap
  eyebrow: L(uz, ru),
  lead:    L(uz, ru),
  visual:  { type: 'column', a: 24, b: 13 },   // СТРУКТУРА, не строка для показа
  options: [...], correct: 2,
  audio: {
    intro:      L(uz, ru),     // ОБЯЗАТЕЛЬНО. Шире экранного текста, не его копия
    on_correct: L(uz, ru),     // ОБЯЗАТЕЛЬНО на экране с ответом
    on_wrong:   [L(uz,ru), …]  // ОБЯЗАТЕЛЬНО свой на КАЖДЫЙ неверный вариант
  }
}
```

Три правила схемы, которые и есть защита от ошибок:

**(1) `audio` обязательно и не выводится из текста.** В 19 эталонных уроках триптих
`intro` + `on_correct` + `on_wrong` встречается на **132 экранах** — это измеренная норма,
а не пожелание. Валидатор обязан падать, если `audio.intro` совпадает со склейкой
`eyebrow + lead + visual`.

**(2) `visual` — структурные данные, не строка.** Строка вида
`'  24\n× 13\n────\n  72'` не должна существовать: она попадает и на экран, и в озвучку.
Отрисовкой занимается сцена, получая `{type:'column', a:24, b:13}`.

**(3) Текст в озвучку идёт только через `kit/verbalize.js`.** Один путь, один набор правил:
`× ÷ = > <` → словами; `— « » % $ ✗ ──── □△◇` → **ошибка валидации**, а не автозамена.
Автозамена прячет проблему, ошибка заставляет написать фразу человеческим языком.

## 5. Практика (amaliyot)

10 заданий на каждый теоретический урок, роли — по `ETALON_3SINF.md` §6:
узнавание → простое применение с опорой → применение в другом виде → вычисление/построение →
поиск пропущенного → текстовая задача → сопоставление/упорядочивание → ноль/граница/ловушка →
поиск ошибки → трансфер.

Минимум 3 разных типа взаимодействия. Одинаковые числа не повторяются в соседних заданиях.
Неверные варианты — не случайные, каждый выражает конкретную неверную стратегию.

Инфраструктура практики 3 класса уже частично общая: `practice/QuestionFactory.jsx` (940 строк),
`practice/PracticeHost.jsx` (465), `practice/PracticeBank.jsx` (218), `practice/sourceRegistry.js`,
`practice/theoryDerivedBanks.js`. Разбирать её до наведения порядка в теории не нужно, но
новые банки писать в этой структуре, а не рядом.

## 6. Известные ловушки — проверено, не предположения

### 6.1. `on_event` — исправление состоит из ТРЁХ частей

В 3 классе уже исправлено ([Dars02.jsx:342–353](src/components/grade3/Dars02.jsx#L342-L353)):

```js
playNext(forced = false) {
  const seg = this.queue[this.currentIdx];
  if (!forced && seg && seg.trigger.indexOf('on_event:') === 0) {
    this.isPlaying = false; return;                        // (1) ждать своего события
  }
  this.playSegment(seg);
}
triggerInternalEvent(name) { … this.playNext(true); }      // (2) событие пришло — играть
pushOneOff(text, gender)   { … this.playNext(true); }      // (3) иначе фидбэк онемеет
```

**Все три части обязательны вместе.** Только (1) без (2)+(3) — урок замолчит: ребёнок
ответит и не услышит разбор. Это хуже исходного бага.

Где баг ещё жив (не для 3 класса, просто чтобы не скопировать оттуда):
`_archive/old-prompts/PROMPT_YANGI_DARS.md:1062`, [src/runtime/lessonRuntime.js:152–155 и :175](src/runtime/lessonRuntime.js#L152-L155),
классы 1, 2, 5, 6.

### 6.2. Аудио как склейка экранного текста — главная ошибка предыдущего каркаса

`Grade3LessonShell` ([Dars19.jsx:470](src/components/grade3/Dars19.jsx#L470)) озвучивает
`title + text + visual + ask`. Реальный результат на данных `Dars22`:

```
в озвучку уходит:  "24 ko'paytirish 13 ──── 72 240 ──── 312"
                   "23 ko'paytirish 10 + 4 ✗"
```

Это нарушает `ETALON_3SINF.md` §2 («аудио **шире** экранной инструкции») и §3 («голос —
основной канал»). Так сделаны **32 из 51 урока** (`Dars19–20`, `Dars22–51`).
По решению методиста от 2026-08-03 они **пока не переделываются** — это зафиксированный долг.

Причина ошибки не в небрежности: в схеме `S(type, title, text, visual, ask, options, correct, hint)`
([Dars22.jsx:5](src/components/grade3/Dars22.jsx#L5)) **нет поля `audio`**. Инструмент
физически не позволял выполнить требование эталона. Отсюда правило §4.2(1).

### 6.3. Раннеры спрятаны внутри файлов уроков

`Grade3LessonShell` живёт в `Dars19.jsx`, `GeometryLesson` — в `Grade3GeometryBlock.jsx`,

`Dars01`–`Dars19`, `Dars21`. Блокировка навигации отключена — ребёнок проматывает

## 7. Определение готовности

Из `ETALON_3SINF.md` §7 плюс проверяемое машинно. Урок готов, когда:

**Методика**
- покрыты все 15 роли; ни одна не пропущена молча;
- на каждом экране одна учебная цель;
- правило даётся после наблюдения хотя бы одной закономерности;
- итоговая диагностика не повторяет числа урока;
- ребёнок активно решает на ≥60% экранов;
- использовано ≥3 типа взаимодействия.

**Язык и аудио**
- UZ — латиница, обращение `siz`, апостроф ASCII `'`, порядок SOV;
- RU — обращение `ты`, форма без привязки к полу;
- `audio.intro` шире экранного текста и не равен его склейке;
- `on_wrong` свой на каждый неверный вариант, указывает на признак, а не даёт ответ;
- в аудио нет `— « » % $ × = ✗ ────`; числа и знаки — словами;
- один сегмент аудио = одна мысль.

**Техника**
- открываются все экраны, число совпадает с метаданными;
- переключение UZ/RU работает на каждом экране;
- при выключенном звуке урок проходится полностью;
- при включённом звуке ответ заблокирован до конца инструкции;
- после неверного ответа можно исправиться и продолжить;
- мобильный и десктоп — основные элементы управления видны;
- в консоли нет runtime-ошибок;
- `FREE_NAV = false`;
- тема, номер и описание совпадают с `src/lessons/grade3.js`;
- `npm run build` проходит.

**Что дал разбор методиста по скриншотам (второй заход, 2026-08-03)** — все четыре замечания
подтвердились, причина в каждом случае оказалась не там, где выглядела:

1. **«Есть скролл»** — при фильтрации CSS выпало правило `.lesson-root { position: fixed;
   inset: 0; overflow: hidden }`. В 1 и 2 классе урок прибит к экрану и внутри скроллится
   только `.stage-content`; без правила прокручивалась вся страница, и «Дальше» уезжала на
   середину. Заодно выпали `.title` (Source Serif 4 у заголовков), `.delay-*` и палец-подсказка
   у числовой прямой. Фильтр отбирал правила по классам, которые упоминает `kit/`, а `.lesson-root`
   ставится в `screens/LessonShell` — его тогда ещё не существовало.
2. **«Размер фрейма Бита не соответствует»** — сам компонент байт-идентичен 2 классу; отличалась
   рамка вокруг: в 3 классе `width: min(780px, 100%)` и по центру (слой `Grade3EtalonDesign`),
   во 2 классе во всю ширину. Это различие класса, зафиксировано в ETALON §6.1.1.
3. **«Когда должен выходить фрейм Бита»** — в уроке 1 второго класса карточка Бита стоит на
   девяти экранах, и на всех девяти ПОСЛЕ ДЕЙСТВИЯ ребёнка; там, где он только смотрел, Бита нет
   вообще. У нас Бит выходил по окончании абзаца объяснения. Исправлено: на показе — спокойная
   заметка, Бит только на действие (ETALON §6.1.1). **Хук** переделан по механике 2 класса: одна
   попытка, варианты исчезают, верный ответ НЕ показывается, «Дальше» открыто после любого
   ответа (ETALON §6.1.2).
4. **«Нет объяснения в озвучке и синхронизации с анимацией»** — экраны объяснения были пассивны,
   а подсветка разряда не была привязана к текущему сегменту. Теперь: подсветка живёт ровно на
   своей фразе (`currentSegment`), а два ключевых открытия ребёнок **собирает руками** —
   десять лент в сотню и десять сотен в тысячу, по механике tap-to-cassette из 2 класса.
   Пока десять не собраны, объяснение молчит (ETALON §3.1, §3.1.1).

**Что дало прокликивание урока в браузере** (то, чего не видно ни в сборке, ни в линте):
- порядок объявлений в извлечённом модуле: `const FLORA` ссылался на компоненты выше по файлу
  и падал с `Cannot access before initialization`. Сборка это не ловит, урок не открывался вообще;
- экран запирался, если озвучка не сообщила о завершении. Из этого выросло правило §10.1 эталона
  и часовой `stalled` в `useAudio`;
- выключенный звук сбрасывался на каждом экране (состояние жило в экране, а не в уроке);
- механика `build_number` в данных была, а в экране её не было: экран 9 показывал пустую рамку;
- блок примеров с решениями (§3.2) лежал в данных и не выводился ни на одном экране.
