# Математический профиль онлайн-эталона (Junior IT Academy)

Дополнение к общему онлайн-эталону для **математических** интерактивных уроков (алгебра, тригонометрия, DTM-подготовка). Те же 9 стандартов, но с матан-механикой вместо HTML/проекта. Эталонный образец — урок «Логарифмик тенгсизликлар» (12-dars).

---

## ⚠️ Как пользоваться этим файлом (это чеклист, а не шаблон)

Этот `.md` — **линейка для проверки готового урока, а не форма для отливки.** Если прогонять каждый урок «под него» механически, получатся одинаковые уроки из-под копирки. Так делать НЕ нужно.

- **Приёмы подачи — не обязательный набор на каждый урок.** Хук-конфликт, работа с чужой ошибкой, оба случая параметра — это инструменты, сработавшие на логарифмах. Не в каждой теме есть «два ответа, кто прав» или параметр с двумя случаями. Приём применяется там, где **тема сама его просит**, а не потому что он есть в файле. Натянутый силой приём ломает урок.
- **Математика и логика темы — всегда первичны.** Если приём из файла конфликтует со смыслом конкретной темы — приоритет у темы. Файл описывает *как подавать*, но не *что верно* в самой математике. Это решает автор.
- **Обязательное vs желательное.**
  - *Must (проверять всегда):* ответ раскрывается после действия · passed = агрегат ≥60% · видимый интерактив и зона клика · подписи осей · чистый рендер формул на мобильном · живой узбекский на «siz».
  - *Гибкое (по теме):* конкретные приёмы подачи — если ложатся.

**Короче:** прогоняйте урок по чеклисту в конце файла, но приёмы берите только там, где тема сама их просит. Файл проверяет качество, а не задаёт единый шаблон — уроки должны оставаться разными.

## Как ложатся 9 стандартов на математику

| Стандарт | В матане это |
|---|---|
| 1. passed = агрегат ≥60% | То же. Один пример не решает «сдал». Индикатор готовности = тот же %. |
| 2. Ученик производит ответ | Не только выбор варианта: сам вводит интервал `( ? ; ? )`, ставит знак, строит точку, собирает решение обратным ходом. |
| 3. Покрытие тестов | Каждая точка — разный узел темы (ОДЗ / направление знака при 0<a<1 / сборка ответа / ловушка). Финал интегративный. |
| 4. Дифференциация | Уровень «повыше» + «Yordam» (подсказка после 2 ошибок). |
| 5. Домашка + рубрика | Путь сдачи + рубрика; «сначала сам, потом проверь». |
| 6. Гейты | Микроподтверждение на ключевом шаге (напр. «в каком случае нужно писать argument>0?»). |
| 7. Контекст → теория | Хук-конфликт до правила (см. ниже). Правило — после. |
| 8. Socratic-тон | Вопрос ученику на «siz», открытие вместе. |
| 9. Связность | Один сквозной пример через весь урок (в 12-dars: `log₅(x−3)<2`). |

## Матан-паттерны, дающие эталон (бери как приёмы)

Все — из урока 12, проверены как рабочие:

1. **Хук-конфликт.** Урок открывается двумя ответами, из которых один — типичная ошибка. «Ikki javob. Kim haq?»: `(3;28)` vs `(−∞;28)`, где второй — «забыл ОДЗ». Весь урок работает на разрешение конфликта. Это сильнее, чем «прочитай правило».

2. **Контрольные точки ДО правила.** Прежде чем дать общее правило, ученик подставляет конкретные числа (x=0/4/128) и сам видит вердикт «kiradi / kirmaydi». Число убеждает раньше формулы.

3. **Оба случая параметра рядом.** Для логарифма/степени с параметром — показать `a>1` (растёт) и `0<a<1` (убывает) одновременно, с интерактивным слайдером. Ученик видит, ПОЧЕМУ переворачивается знак, а не заучивает.

4. **Работа с чужой ошибкой.** «Qadamlar to'g'ri, javob xato»: даётся почти верное решение с одним пропущенным условием (ОДЗ), ученик ищет, какое правило нарушено. Тренирует ровно ту ошибку, на которой сыпятся на DTM.

5. **Обратная сборка.** «Teskari yig'ing»: от готового ответа `(3;7)` собрать запись решения. Проверяет понимание, а не механику прогонки.

6. **Метод контрольных точек как визуал.** Числовая прямая с точками и подписью «qo'ydik x=… → chapda chiqdi… → kerak… → KIRADI/KIRMAYDI». Наглядно и честно.

## Матан-специфика онлайн-механики (частые дефекты — проверяй)

Из ревью тригонометрии и логарифмов:

- **Ответ-спойлер до действия.** Координаты/градусы/интервал НЕ показывать, пока ученик не поставил точку/не ввёл. Показывать после верного действия. (Частый дефект: `30° → (√3/2; 1/2)` висит рядом с заданием «сам найди».)
- **Видимая точка и зона клика.** На экранах «поставь точку на круге» — маркер виден в старте (можно «призрак» на 0°), окружность подсвечена как кликабельная. Без этого экран не проходится.
- **Подписи осей.** На тригонометрическом круге / графике подписать x(cos)/y(sin) или оси функции — ученик по ним принимает решение.
- **Заголовок не должен утверждать ложное.** «Одна точка, два прочтения» неверно, если при перестановке координат получается ДРУГОЙ угол. Заголовок-факт не должен толкать к неверному ответу.
- **Живой счётчик, если обещан.** «Следи за счётчиком» → счётчик реально пересчитывает число при движении точки (напр. `cos²+sin² = … = 1.00`), а не статичная формула.
- **Рендер формул.** Индексы оснований (log₀,₅), степени, √ — не должны разъезжаться; плотные примеры (несколько равенств в строке) разводить переносами. Проверять на мобильном.
- **Единый формат ответа.** Не смешивать дроби (1/2, √3/2) и десятичные (0,5) как ввод одного и того же значения — выбрать один либо принимать оба.
- **Единый стиль капса** (KERAK, KICHIK) по всему курсу.

## Узбекский в матане (тон)

- «siz», живой язык, без кальки.
- Пары формулировок — симметричны: «logarifm belgisini olib tashlash, ishora o'zgarmaydi» ↔ «…ishora o'zgaradi».
- «o'ng tomonni logarifmga aylantirish» (не «o'ngni…»).
- «Javobni oraliq ko'rinishida yozing» (не «oraliq bilan»).

## Мини-чеклист ревью матан-урока

1. Есть хук-конфликт до правила? 
2. Контрольные точки идут раньше общего правила?
3. Оба случая параметра показаны (если есть параметр)?
4. Есть экран «найди чужую ошибку» (ОДЗ / знак)?
5. Ответ раскрывается после действия, не до?
6. Точка/зона клика видны; оси подписаны?
7. passed = агрегат ≥60%, индикатор совпадает?
8. Формулы рендерятся чисто на мобильном?
9. Узбекский живой, пары симметричны, «siz»?
