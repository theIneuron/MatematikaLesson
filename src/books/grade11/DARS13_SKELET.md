## Что здесь нового

Первые четыре урока блока учили решать **одну** запись. Тринадцатый — первый, где записей
две, и главное слово урока: **система — это И, а не ИЛИ.** Отсюда две формы ответа, и обе
на ДТМ встречаются:

| Форма системы | Ответ | Где в уроке |
|---|---|---|
| два неравенства с одним `x` | **пересечение** промежутков | экраны 1–5, 9–11 |
| два уравнения с `x` и `y` | **пара чисел** | экраны 6–8 |

Пересечение видно на одной прямой — это ровно то, ради чего в классе есть `SolutionLine`.

## Паспорт

- **Класс:** 11. **Блок:** Б2, урок 13. **Экранов:** 15. **Голос:** мужской.
- **Оценивается:** блиц (экран 12). Ссылок на учебник на экране нет.
- **Все неравенства урока строгие** — иначе ответ был бы вида `[3; 9)`, а прибор записи
  ответа рисует круглые скобки. Смешивать формы записи в первом уроке про системы нельзя.

### Задачи и сверка

| Задача | Ответ | Проверка |
|---|---|---|
| `2ˣ > 8` и `log₂ x < 4` | `(3; 16)` | `x = 4` проходит оба, `x = 20` и `x = 2` — нет |
| `2ˣ⁺ʸ = 8` и `x − y = 1` | `x = 2, y = 1` | `2³ = 8` ✓, `2 − 1 = 1` ✓ |
| `5ˣ < 125` и `log₅ x > 0` | `(1; 3)` | `x = 2`: `25 < 125` ✓, `log₅ 2 > 0` ✓ |

Задачник даёт систему `2^(log₂(3x−4)) = 8`, `log₉(x²−y²) − log₉(x+y) = 0,5` с ответом
`(4; 1)` — ключ 33 ✓. В урок она **не берётся**: там сразу два тождества, которых в блоке
не было. Место ей — в банке практики.

## Пять заблуждений

| Код | Заблуждение | Как выглядит | Тег |
|---|---|---|---|
| З1 | объединение вместо пересечения | из `x > 3` и `x < 16` собрал всю прямую | `intersection` |
| З2 | решил только одно условие | ответ `(3; +∞)` | `intersection` |
| З3 | забыл, что логарифм сам требует `x > 0` | `log₂ x < 4` → `x < 16` без нижней границы | `log_domain` |
| З4 | в системе с двумя неизвестными проверил только одно уравнение | пара `(1; 2)` принята | `check_by_point` |
| З5 | не увидел, что пересечение пусто | вместо «решений нет» пишет границу | `intersection` |

Новых тегов нет.

### Ключевые кадры

**Экран 3.** Три точки, и каждая проверяет своё. `x = 4` проходит оба условия — это решение.
`x = 20` проходит первое (`2²⁰` заведомо больше восьми) и не проходит второе (двадцать
больше шестнадцати). `x = 2` не проходит уже первое. Ученик видит: решение системы — число,
которое прошло **оба** испытания, а не хотя бы одно.

**Экран 4.** График второго условия. Кривой левее нуля нет, прямая `y = 4` пересекает её при
`x = 16`, и тень получается двусторонней: `(0; 16)`. Именно здесь ученик видит, что
логарифмическое неравенство само по себе уже даёт **два** ограничения, и нижнее он обычно
теряет.

**Экран 7.** Два кандидата: `(2; 1)` и `(1; 2)`. **Первое уравнение не различает их вообще** —
сумма в обоих случаях три. Различает второе. Это и есть ответ на вопрос «зачем в системе
второе уравнение». Ученик записывает пару: `x = 2`, `y = 1`.

**Экран 13.** Ошибка в середине:

```
  1)  2ˣ > 8,   log₂ x < 4
  2)  x > 3
  3)  x < 16
  4)  x > 3  ИЛИ  x < 16        ← ошибка
  5)  ответ: вся прямая
```

Доказательство: `x = 20`. Первое условие выполняется, второе нет — значит двадцать решением
не является, а в ответ оно входит.

вариантов для этого годится.

## Приборы

Доработка одна: **`AnswerValue` получил метки по ячейкам** — `x = ⬚`, `y = ⬚`. Без них пара
записывалась бы как «x = 2 и 1», то есть неверно по смыслу. Там же появился порядок: с
метками `(2; 1)` и `(1; 2)` — разные ответы, без меток (два корня) порядок по-прежнему не
важен.
